## 2024-10-23 - [O(N*M) Overhead in Asset Relationship Calculation]
**Learning:** By chaining `Array.map`, `Array.filter`, and `Array.some` continuously inside looping constructs for text matching logic (e.g., matching hotspot titles against known asset types), the application created massive intermediate closures and re-allocated arrays over and over. Also, simple things like `toTitleLower` were being calculated per asset candidate instead of being hoisted.
**Action:** When implementing performance optimizations for text-matching algorithms in hot paths, explicitly watch out for array function chaining, and refactor using traditional, allocation-free `for` loops. Always hoist normalizations like text lowercasing up into the calling function so they run once per dataset rather than once per evaluation block.
