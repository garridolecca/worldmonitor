## 2024-03-21 - Memory allocations in tight nested loops
**Learning:** The news clustering algorithm (`clusterNewsCore`) uses `jaccardSimilarity` in an O(N^2) inner loop. The previous implementation of `jaccardSimilarity` created two new `Set` objects per call using spread syntax: `new Set([...a].filter(x => b.has(x)))` and `new Set([...a, ...b])`. This created severe garbage collection overhead in this performance-critical hot path due to intermediate array and set allocations. Memory explicitly highlights: "Utility functions used within it (like jaccardSimilarity) must maintain O(1) memory allocation to minimize intermediate memory allocations and GC overhead."
**Action:** When working in deep O(N^2) inner loops like `clusterNewsCore`, avoid intermediate allocations entirely by using mathematical properties (like |A U B| = |A| + |B| - |A n B|) and manual iterations, preventing garbage collection spikes.
